# tmp-20261106-k01

This temporary replay option is available on Anthropic channels. Set the
`TMP_20261106_K01_FIXTURE_FILE` environment variable to the external JSONL file
before starting the server, then enable `tmp-20261106-k01` in the channel
settings.

Saving an enabled Anthropic channel validates that the environment variable is
set and that the referenced file is readable and contains valid JSONL fixture
records. Runtime fixture errors fall back to the upstream; an unchanged file
version produces at most one error log entry.

When enabled, the relay compares the complete incoming request JSON with the
`request` objects in the file. Object key order and insignificant whitespace do
not affect matching; array order and JSON values do. JSON numbers compare by
numeric value, so `1`, `1.0`, and `1e0` match. A missing `status` means 200;
recorded statuses from 100 through 599 are accepted. A 200 match replays the
record's `response` through the normal Anthropic response and billing path for
both SSE and non-streaming records. Non-200 matches return the recorded status
and JSON response body unchanged, without retrying or billing. The first
matching record in file order is used. Non-matching requests continue to the
configured upstream.

The fixture file is loaded at runtime by the host and is not part of the
repository or application build. Replay hits are marked for all users as
`other.replay_hit: true`. Responses also include `X-New-Api-Replay: k01` for
streaming, non-streaming, and non-200 hits.
